# M2 marketing acceptance

Run against the seeded local Compose shop (`make up && make seed`), with the full browser suite from `make e2e`. `pnpm verify-merge <PR#> --full` runs that same unfiltered target against a seeded throwaway stack, so these specs are included. Playwright uses four workers, no retries; specs that mutate the demo flow clock or settings run in the one-worker `chromium-shared-state` project after the regular project. Each test uses a unique address or record and waits for a current message, response or job state.

## Performance and accessibility

After `make seed`, run `bash scripts/seed-m2-perf-review.sh` (also wired in CI). It adds one published review tied to a delivered order line on the measured PDP, idempotently. The `make perf` gate then measures home, category, product and search over HTTPS with three serial mobile Lighthouse runs, scroll-triggered JS accounting (A26), third-party origin checks and axe. The PDP includes recommendations, a populated review section and the watch form; home includes recommendation slots.

## Verification

`make lint test` passed: 682 Rust tests (nine existing ignored), 359 TypeScript tests. Three consecutive unfiltered `make e2e args='--workers=4'` runs against the same retained database passed **109/109, 109/109 and 109/109** (7.7, 7.7 and 7.9 minutes; no skips or retries). `make perf` passed as recorded above. The earlier WP21 image smoke run covered freshly built Rust, mocks, theme-builder and auth images; this acceptance correction changed no image code.

The coupon bug was specific to the dev test clock: a flow executed in simulated future time minted a coupon whose `starts_at` was also in the future, while checkout checked real time and rejected the code as inactive. `commerce::flows::issue_coupon` now starts its redemption window at actual issuance time; the browser regression advances through all three reminders, redeems the emailed code in a paid order and rejects reuse in a second order.
