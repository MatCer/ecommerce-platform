# M3 acceptance traceability

The local suite runs with `ANTHROPIC_API_KEY` empty, so the scripted fake AI uses the same
proposal, agent-loop, revision, builder and publication interfaces as a real provider. CI's
`acceptance` job runs `make e2e` and `make perf` on the seeded Compose stack. The browser suites
are serialized where they mutate the shared demo theme (`chromium-themes`) or catalog prices
(`chromium-shared-state`), with no retries.

| M3 criterion / abuse case | Real interface evidence | Lower-level limit evidence |
|---|---|---|
| Description and translation proposal, review before apply, AI mark | `e2e/admin/ai.spec.ts`: product editor, proposal preview, selective accept, translation glossary and labels | `crates/commerce/tests/ai.rs`: stale proposals, tenant isolation and validation |
| Bulk plan preview then explicit apply; quota exhausted | `e2e/admin/ai.spec.ts`: unchanged prices before confirm, prices/history/audit after, 402 shown in product and bulk screens | `crates/commerce/tests/ai.rs`: quota and price caps |
| Theme fork, token edit, gates, preview authorization, publish/rollback | `e2e/admin/themes.spec.ts`: admin actions, real builder reports, preview iframe, storefront before/after | `crates/commerce/tests/themes.rs`: revision and tenant guards |
| Hostile archive, foreign fetch, build network attempt, JS budget | `e2e/admin/themes.spec.ts`: upload and build failures with reasons | `apps/theme-builder/test/policy.test.ts`: Docker create escape cases |
| Merchant functional check cannot read Mailpit | `e2e/admin/themes.spec.ts`: check runs in its sandbox, spoofs `Host: mail.localhost`, receives 403 | `docker/caddy/PreviewOnly.Caddyfile`, separate `theme-functional` network |
| AI prompt → file edits + functional check → report/diff → accept → publish → rollback | `e2e/admin/theme-ai.spec.ts`: real admin and storefront, functional step passed in builder report | `crates/commerce/tests/theme_ai.rs`: publish gate |
| Turn, repair, token/cost budgets; cancel; tool/path scoping and a prompt injection inside a theme file | `crates/api/tests/themes.rs` exercises start/list/detail/cancel/accept through HTTP. `crates/commerce/tests/theme_ai.rs` scripts the same loop/tool boundary, including a `read_file` result containing instructions to read `../../.env` and overwrite `package.json`; both tools are refused | Browser covers the successful run; limit and injection simulations remain database integration tests |

`make perf` checks the default theme. Full source revisions pass the builder budget,
axe and purchase smoke gates before they become `ready`. Token-only revisions use the
fast path: they inherit the already validated source and skip Lighthouse and purchase
smoke while still running the applicable token and build checks. The browser suites
verify reports on a fork and an AI revision. Hosted edge runtime limits and real provider behavior are separate pre-launch
requirements in `docs/runbook.md`.
