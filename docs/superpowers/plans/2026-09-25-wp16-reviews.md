# WP16 Reviews: implementation plan

> For agentic workers: execute task by task with TDD (failing test, minimal code, green,
> refactor). Commit after every task.

**Goal:** verified product reviews (spec §7.6, §11.6-§11.7, §14, A2, A4, A20): single-use,
expiring review tokens issued per delivered order line (the API WP19's invites call), a
token-gated submission form on the checkout origin, plain-text sanitized and rate-limited
submission, an admin moderation queue (publish / reject / hide, optional merchant reply),
published reviews + rating summary on the product page model and in the default theme,
`AggregateRating` + `Review` JSON-LD (published reviews only), and the Omnibus "how we verify
reviews" disclosure (legal template from WP13a, rewritten; linked next to the reviews).

## Architecture

- Migration `20261016000000_reviews.sql` (RLS + FORCE + grants, composite FKs):
  - `review_tokens(order_line_id PK part, order_id, product_id, token_hash unique, expires_at,
    used_at)`: one live token per order line; re-issuing an unused one rotates the hash.
  - `reviews(product_id, order_line_id unique null, customer_name, rating 1..5, title, body,
    status pending|published|rejected|hidden, verified, locale, reply, replied_at,
    moderated_at, moderated_by, ip_hash)`; partial index for published per product.
  - `customer_auth_attempts.kind` += `review` (per-IP submission cap).
- `commerce::reviews` (one module):
  - `issue_tokens(tx, order_id, now) -> Vec<IssuedToken { order_line_id, product_id, token,
    expires_at }>`: only for `delivered` orders, one per product bought (its first line; one
    review per product and order), live product, not yet reviewed.
    This is the WP19 entry point (invite links = `ctx.checkout_url("/review?token=…")`,
    helper `review_url`).
  - `invitation(tx, token)` (read, no change) and `submit(tx, ctx, token, input, ip_hash)`:
    token consumed atomically (`UPDATE … WHERE used_at IS NULL AND expires_at > now()
    RETURNING`), input normalized to plain text (control chars stripped, whitespace
    collapsed, length limits), per-IP hourly cap, review `pending`, `verified = true`.
  - Moderation: `list(status, cursor, limit)`, `moderate(id, action)` with an exhaustive
    transition table (publish from pending/rejected/hidden, reject from pending, hide from
    published), `reply(id, text|null)`; audit log + `review.changed` outbox event (purges the
    product's cached pages).
  - Storefront: `product_reviews(product_id)` → summary (avg, count, histogram) + latest 20
    published; product page model gets `reviews` + JSON-LD `aggregateRating` / `review`
    (published only; omitted with zero reviews) + `verification_url` (the published legal
    `reviews` page).
- Legal: `reviews` templates (cs/sk/en) describe the actual verification; go-live requires
  the page once any review is published.
- API: storefront `GET /reviews/invitation?token=`, `POST /reviews`; admin `GET /reviews`,
  `PATCH /reviews/{id}` (status and/or reply).
- Edge (checkout origin): `/_p/reviews` form POST → API → 303 back to `/review`; checkout
  binding allows `GET /reviews/invitation`. Checkout page `/review?token=` (no JS form).
- Theme: rating line under the title (links to `#reviews`), reviews section (summary,
  histogram, list with verified badge + merchant reply, disclosure + link).
- Admin SPA: Marketing → Reviews (status filter, publish/reject/hide, reply).

## Global constraints

- Business logic only in `commerce`; tenant tables only via `tenant_tx`.
- Tokens: `capability` (256-bit, SHA-256 at rest), single use, 90-day expiry.
- Review text is stored as plain text and always escaped on output (Astro, JSON-LD
  serializer escapes `<`); never rendered as HTML.
- Only `published` reviews leave the admin API (page model, JSON-LD, summary).

## Review focus

- Token consumption race (double submit) and cross-tenant token use.
- Sanitization/limits, rate limit, no HTML injection into JSON-LD or the theme.
- Moderation transitions, cache purge, JSON-LD per Google rules.
- RLS + cross-tenant tests for `reviews` and `review_tokens`.
