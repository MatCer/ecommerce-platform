# WP19 Flows — backend implementation plan

## Global Constraints

- Build on `commerce` tenant transactions and the existing queue/outbox and mail pipeline. All business decisions live in `crates/commerce`.
- Apply spec §20, especially A1, A2, A8, A14 and A20. Consent is read again at each send. Tenant tables use RLS and FORCE RLS.
- Keep production time real. The test clock is local/dev/test only, rejected by production configuration.
- Backend scope: Rust, schema, API, OpenAPI/clients, token-link edge/checkout routes, email, tests. Admin and theme visual UI belong to the next agent.
- Run with `CARGO_BUILD_JOBS=6`; use isolated `wp19` compose ports and `10.213.19.0/24`; commit each task with the requested trailer.

## Review Focus

- Tenant isolation, token hashing/single use, consent withdrawal between scheduled steps, duplicate outbox/job delivery, order/empty-cart exits, bounded retry and SMTP uncertainty.
- The test clock cannot affect production or another tenant. Run timestamps remain monotonic.
- Watch thresholds compare the committed previous/current stock or price, not an untrusted browser assertion.

## Task 1 — Durable flow schema and core service

Files: `migrations/20261019*.sql`, `crates/commerce/src/flows.rs`, `crates/commerce/tests/flows.rs`.

1. Add tenant-scoped flow definitions/configuration, runs, step executions, and watchdog subscriptions with composite FKs, unique idempotency anchors, RLS + FORCE.
2. Implement configured step schedules, enrollment, cancellation/exit, and state transition methods taking `&mut TenantTx`.
3. Test duplicate enrollment, cross-tenant access, step retry/terminal state, consent withdrawal, and run exits against Postgres.

## Task 2 — Event wiring and mail actions

Files: `crates/worker/src/{outbox,handlers,cron}.rs`, `crates/commerce/src/{flows,notifications}.rs`, order/cart/inventory/price event emitters.

1. Subscribe to cart/order/delivery/inventory/price events; schedule due steps with existing `queue.enqueue` and idempotency keys.
2. Make abandoned cart reminders with signed restore capability and optional one-use coupon; check `email_marketing` for each step and stop on order, unsubscribe or empty cart.
3. Double opt-in watch subscription, back-in-stock/price-drop single fire, one-click unsubscribe.
4. On review invite due date check `review_invites`, call `reviews::issue_tokens(tx, order_id, now)`, and queue one review URL per product.
5. Test event duplication and end-to-end job to mail behavior.

## Task 3 — HTTP contracts and token links

Files: `crates/api/src/{admin_flows,storefront/flows}.rs`, `apps/edge/src/gateway.ts`, checkout origin routes, OpenAPI/generated client files.

1. Expose permission-gated tenant admin listing/configuration/run endpoints and storefront watch subscribe/confirm/unsubscribe endpoints.
2. Expose checkout-origin restore-cart token route with no-store and safe redirects.
3. Regenerate OpenAPI and clients; test auth, tenant isolation, invalid/expired/replayed token links.

## Task 4 — Development clock and verification

Files: `crates/commerce/src/flows.rs`, API/worker configuration and tests, WP16 e2e.

1. Add dev/test-only clock advancement for scheduled work; reject all production requests regardless of credentials.
2. Replace WP16 e2e SQL token workaround with invite flow only once equivalent behavior is demonstrated.
3. Run focused tests, `make lint test`, relevant e2e on the isolated compose stack; bring `wp19` down with volumes and report remaining UI integration.
