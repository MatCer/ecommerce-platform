# WP7 Search: implementation plan

> **For agentic workers:** execute task by task with TDD; commit after every task.

**Goal:** Meilisearch-backed product search for the storefront: per-variant documents, a
cs/sk normalizer, an outbox-driven indexing pipeline with versioned full rebuilds, a
variant-correct query service rehydrated from Postgres, Storefront search/suggest endpoints,
Admin rebuild/status endpoints and degraded-mode readiness.

**Spec:** §11.1, D6, §17 WP7, amendments A23 (documents), A27 (Meilisearch ops), A20 (no
personal data), A30 (search out of core readiness).

## Global Constraints

- Business logic in `crates/commerce/src/search/`; `api` parses, authorizes, calls; `worker`
  registers handlers. No `unwrap()` outside tests, `thiserror` errors, clippy `-D warnings`.
- Meilisearch through a thin `reqwest` client (`search::meili`), not `meilisearch-sdk`:
  `reqwest` is already a workspace dependency, we need ~10 endpoints, and the SDK pins its own
  HTTP stack and lags server features we rely on (granular `filterableAttributes`,
  `distinct` per query, multi-search).
- Keys (A27): the API holds only a search key (`MEILI_SEARCH_KEY`, actions `search` on
  `t_*`), the worker an admin key (`MEILI_ADMIN_KEY`). A one-shot `meili-init` compose service
  creates both from fixed uids (key value = HMAC-SHA256(master, uid), precomputed in
  `.env.example`). The master key never reaches api/worker.
- Index names `t_<tenant uuid>_<locale>` (A27). Rebuilds build `…__r<job id>` and swap.
- New tenant tables get `tenant_id`, `tenant_isolation`, ENABLE + FORCE RLS and a
  cross-tenant test. Zero-result log stores tenant, day, locale, normalized query, count only.
- Search is a degraded component: `/readyz` reports `status: degraded` (HTTP 200) when only
  Meilisearch fails; search endpoints answer 503 `search_unavailable`.

## Design decisions

- **Documents (A23):** one per (sellable variant, locale). Fields: `id` (variant), `product_id`,
  `skus`, `eans`, `name_folded`, `name_stems`, `brand`, `text_stems` (brand, categories,
  text parameters, description), `category_ids` (direct + ancestors), `opt.<code>` (variant
  option value codes), `param.<key>` (filterable parameters, variant value overrides product
  value), `price.<market>` (effective gross minor units now, market code with `-`→`_`),
  `in_stock`, `active_in_markets`, `popularity` (0 placeholder), `created_at`. A variant is
  indexed only if its product is `active`, has a translation in the locale and the variant has
  an effective price in at least one market's price list.
- **Settings are versioned** (`SETTINGS_VERSION`); `ensure_indexes` (re)applies them when the
  stored version is older. `distinctAttribute = product_id`; searchable in rank order
  `skus, eans, name_stems, name_folded, brand, text_stems`; typo tolerance off for
  `skus`/`eans`; `opt`, `param`, `brand`, `category_ids`, `in_stock`, `active_in_markets`,
  `id`, `product_id`, `skus`, `eans` filterable, `price.*` with comparison; `price`,
  `popularity`, `created_at` sortable. Synonyms: per-tenant placeholder (empty).
- **Normalizer (`search::lang`):** lowercase → fold diacritics → tokenize on non-alphanumerics
  → drop cs/sk stopwords → light suffix stemmer (Dolamic & Savoy light Czech stemmer as in
  Snowball/Lucene, rules rewritten for folded text, plus Slovak case endings). The same
  function builds `*_stems` at index time and the query text at query time.
- **Exact SKU/EAN first:** a query that is one token also runs an exact
  `skus = "<q>" OR eans = "<q>"` filter query in the same multi-search; its products are
  placed first.
- **Incremental indexing:** the outbox dispatcher maps `product.*`, `price.changed`,
  `inventory.changed` (payload gains `product_id`) to `search.index_product` jobs with a
  debounce idempotency key `search:<tenant>:<product>:<2 s bucket>` and `run_at` = bucket end
  + 2 s. `category.*` → `search.reindex_category` (products whose docs carry that category id,
  found in Meilisearch, plus current Postgres members). `parameter.*`, `market.*`,
  `price_list.*` → debounced `search.rebuild`.
- **Stale versions:** the job id is the version (it is allocated by the dispatcher after the
  source transaction committed). The handler locks `search_product_state(tenant, product)`,
  drops the job if `indexed_version >= job.id`, otherwise reads Postgres, enqueues the
  Meilisearch writes (add docs, then delete the product's docs not in the new id set) and
  records the version, all under the row lock, so Meilisearch receives writes per product in
  version order.
- **Rebuild with swap:** job `search.rebuild` creates `…__r<job id>` per locale, records it as
  `building_uid`, streams products in batches (row locks as above, writes to the new index),
  waits for the tasks, then under an exclusive per-tenant advisory lock swaps all locales in
  one `swap-indexes` call, clears `building_uid` and deletes the old index. Incremental jobs
  take the same lock shared and write to live + building indexes, so no update is lost.
- **Query:** one multi-search: hits (filters, `distinct=product_id`, page/hitsPerPage, sort),
  facet availability without distinct (`distinct=id`, limit 0) for the full filter set, one
  query per selected facet with that facet's own filter removed (multi-select OR within a
  facet, AND across facets), a universe query (base filter only) for the value list, and the
  exact SKU/EAN query. Values in the universe but not available → `available: false`.
  Results are rehydrated from Postgres (active, translated, current price in the market's
  price list, stock, first image); anything no longer visible is dropped.
- **Storefront context:** `x-tenant`, `x-market`, `x-locale` as injected by the edge. Until
  WP6's storefront-token check lands, the router accepts a context only for an active tenant
  whose market has a verified domain and whose locales include the locale.

## Tasks

1. Plan (this file).
2. `search::lang` normalizer + unit tests; `fixtures/search/cs-sk-queries.tsv` (+ catalog).
3. `search::meili` client, settings, index naming; migration (`search_indexes`,
   `search_product_state`, `search_zero_results`), RLS test.
4. Document builder (Postgres → docs) + unit tests on the pure part.
5. Indexing: `index_product`, `reindex_category`, `rebuild`, worker handlers, dispatcher
   subscribers, `inventory.changed.product_id`; integration tests (ignored, real Meilisearch).
6. Query service + adversarial tests (A23) + fixture test (ignored, real Meilisearch).
7. API: storefront router (`/storefront/v1/search`, `/search/suggest`), admin
   (`POST /admin/v1/search/rebuild`, `GET /admin/v1/search/status`), readiness degraded,
   zero-result recording; config + compose (`meili-init`, keys); OpenAPI + clients.
8. `make test-search`; verification on the stack; Astra review; PR.

## Review Focus

- Variant correctness of filters and facet availability (cross-variant false matches).
- Stale-write ordering between incremental jobs and rebuild/swap.
- Filter-string injection (all values quoted and escaped; keys validated).
- Tenant isolation: index names derive from the tenant context only; RLS on new tables.
